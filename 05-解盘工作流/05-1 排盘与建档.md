# 05-1 排盘与建档（守门员流程）

> **【AI 执行指令】**
> 本文件是解盘的**必经入口**。未完成排盘建档与用户确认前，**禁止进行任何分析**。
> 排错一宫，全盘皆错——本步是整个工作流最不可省的一步。
> 排盘一律由**贞观紫微引擎**（Node CLI `ziwei-chart/engine-cli.mjs`）完成，**禁止识图、禁止依赖文墨天机、禁止凭生辰八字自行推算**。
> **node 可用性**：本文件所有 `node engine-cli.mjs` 调用一律按《05-0》第一节做跨平台查找并替换为 `"$NODE_BIN" engine-cli.mjs`，禁止裸用 `node`。

---

## Step 0.1 强制输入

调用 skill 后，首先要求用户提供**生辰**（阳历年月日时分 + 性别 + 出生省市）：
> "请提供生辰：阳历出生年月日时分（如 1990-05-05 14:30）+ 性别 + 出生省市（用于真太阳时校正）。要素不全无法开始排盘。"

- 用户未提供 → 不往下执行。
- 时分缺 → 索要（影响真太阳时校正）。
- 省市缺 → 默认按北京（**116.4°E**）并告知用户"按北京经度排盘，如有出生地请补充以校正真太阳时"。
- 早晚子时存疑（23:00-01:00 跨日）→ 须确认出生日所属日期。
- 性别影响大限顺逆，**禁止凭生年干阳阴自行推断性别**——必须用户明示。

## Step 0.2 调引擎排盘

按《05-0 引擎调用规范》先做 node 可用性检查（三步法），再调 CLI 取本命 JSON：

```bash
node ziwei-chart/engine-cli.mjs <年> <月> <日> <时> <分> <male|female> [省] [市] --format json --name <命主名>
```

引擎内部经 `calcTrueSolarBranch(年月日, 时, 分, 经度)` 算真太阳时（含经度校正 + 均时差）→ 时辰索引 → `astro.bySolar` 排盘。agent 永不自行算时辰。

同时生成预排盘 HTML 给用户看：
```bash
node ziwei-chart/engine-cli.mjs <参数同上> --format html --out ./<命主名>-<YYYYMMDD>-排盘.html
```

HTML 为单文件内联版（file:// 双击可用，无 CORS），present 给用户对照查看。**HTML 仅供视觉对照，agent 分析一律读 JSON / 记录 md，不读 HTML 状态**。

## Step 0.3 交叉校验（引擎自校 + 抽查）

> **【查表强制·禁止凭记忆】**（违反必出错，2026-07-25 回归已验证）
> - 涉及**生年四化** → 引擎 palaces[].stars[].siHua 已含生年四化标注，但分析前**必查《03-1 十天干四化表》**核对照（曾错把丙干四化记成甲干：廉禄破权武科阳忌，实为同禄机权昌科廉忌）
> - 涉及**三方四正** → 必查《02-2》开头公式**或该文件第一节"三方四正映射表"**（二者恒等价：公式为权威定义、表为已校验展开；首选查表免 mod 运算），禁止凭记忆推地支关系
> - 涉及**星曜庙旺落陷** → 一律以引擎输出 `star.brightnessText`（庙/旺/平/陷）为准；知识库不内置地支表
> - **命主星 / 身主星** → 引擎不输出，**禁止记录入档**（与命宫主星/身宫主星是不同概念，记录易混淆污染盘面）；分析一律以命宫主星、身宫主星为准

引擎输出已确定性，无需像识图模式那样逐项识别。校验工作收窄为：
1. 核对 `lunarInfo.ganzhiYear` 干支与《03-1》生年四化星是否一致（引擎已含，但仍查表防 agent 记错）。
2. 用《02-2》公式抽查 2–3 组三方四正关系，确认引擎 `oppositeBranch` 等字段正确（首次排盘必查，建立信任后可省）。
3. 发现引擎输出明显异常（如命宫无主星且空宫借星错乱）→ 中断，先排查调用参数，不在分析层强行解释。

## Step 0.4 生成记录 md（建档）

按附录模板生成 `./命主名-YYYYMMDD-解盘记录.md`。
- 字段填充源：JSON → md 映射见《05-0 第四节》。
- **此后所有分析一律读记录 md，不再重复调引擎取本命盘**；发现记录有误时，先改记录 md 再继续。
- **记录 md 是本会话命盘的唯一事实源，三种情况必须重读它而非凭记忆**：①上下文压缩／会话恢复／续聊之后，首次引用盘面数据（星曜、亮度、四化、格局、档位）前；②距上次引用盘面已隔多轮对话时；③用户质疑盘面数据时。凭记忆复述盘面属违规——语气笃定的错数据比不答更危险（实证：会话压缩后凭记忆复原，把命宫主星记错）。
- 预排盘 HTML 路径记入记录 md 头部，方便用户随时打开对照。

## Step 0.5 强制中断·用户确认

向用户复述建档内容（生辰/真太阳时差/命宫/身宫/五行局/十二宫主星/生年四化/自化/大限区间），**强制中断**：
> "以上是排出的本命盘（已生成预排盘 HTML 供你对照查看）。请逐项核对生辰与命身宫四化。确认无误后我开始分析；有误请指出哪一项，我修正后重新排盘。"

- 用户确认无误 → 进入 Step 0.6（先 0.6-1 发展地追问，后 0.6-2 可选访谈）。
- 用户指出错误（多半是生辰/性别/省市错）→ 改参数重调引擎 → 刷新记录 md → 再次复述确认，直至无误。

## Step 0.6 情境校准（同盘不同命之解）

> **【AI 执行指令】** 盘面是地形结构，情境是出发点——同一张地图从不同位置出发，路线完全不同。本步分两段：0.6-1 发展地追问（强制）→ 0.6-2 情境访谈（可选）。**只校准呈现与出口转译，不改档位**。

### 0.6-1 发展地追问与环境检索（强制，不可跳过）

盘面确认无误后，**必先追问发展地，再进入任何分析**：

> "为了把断语落到你真实的生活环境（同一张迁移宫、官禄宫，在大陆／香港／美国的呈现完全不同），请告诉我：你目前在哪个国家、哪个城市发展？或打算去哪里发展？"

**执行规则**：
- 此问**必问一次**。用户答了 → 立即**联网检索**该国家/城市的当下实况，维度：**文化背景／经济情况／产业情况／人口流动情况**（按需取要，注明检索日期），摘要写入记录 md 情境档案「发展地」与「环境检索摘要」。
- **三元九运不检索**：时间运全球统一，按《00-5》第一节锚点公式推算所问年份之运、查九星对照表取象；地区方位旺衰标〔流派参考〕，禁作定论。
- 检索结论供迁移/官禄/财帛/夫妻四宫断语作取象转译，**只转译出口，不改档位**（《00-5》第二节）。
- 用户明确表示不方便说 → 标注"未提供（已问一次）"，按出生国默认语境解读，**此后任何环节不再追问**。
- 检索摘要只入记录 md，不进 HTML 报告。
- **0.6-1 完成后（无论用户已答或拒答），必须接着列出 0.6-2 五问**——0.6-2 的回答可全跳，但"列出访谈"这一动作**不可省略**，不得从 0.6-1 直接进入本命分析。

### 0.6-2 情境访谈（问题可选答，列出不可省）

一次性列出以下 5 问（**全部可选**，不设门槛，跳过不阻断分析——"可选"指**命主可选答**；对 AI 而言，**列出五问是必做动作**）：

> "为了让解读更贴合你的实际情况（同样的盘在不同处境下呈现差异很大），方便的话简单说下：
> ① 家庭与成长环境（大致城乡/家境/独生与否）
> ② 教育与职业现状（行业/体制内外/所处阶段）
> ③ 近年有无重大转折（搬迁/转行/婚恋变化等）
> ④ 当前最关心哪方面（事业/财/感情/健康，选一两个）
> ⑤ 是本人咨询还是代问（代问请说明与命主关系）
> 不方便说的直接跳过即可，不影响排盘。"

**执行规则**：
- 一次全列，**禁止逐问追问**（命主答到哪算哪）。
- 跳过的问题在记录 md 情境档案中标注"未校准"，三解按默认排序。
- **代问**：可代问，但情境档案标注"代问，情境信息为二手"；三解排序降可信度处理，措辞收敛（《00-1》四之三第 7 条）。**疑似代问而未明**（如全程第三人称、语境露馅）时：最多询问两次；两次未答 → 默认按"本人＋中性收敛措辞"处理并标注存疑，**此后不再追问**（纠缠式追问破坏体验，中性措辞已能兜底两种身份）。
- **禁止以盘验人**——不得用盘面反推命主现实来"验证"其自述。
- 情境信息**只入记录 md，不进 HTML 报告**（报告可能被分享转发）。
- 收到回答（或明确表示都不方便说）→ 摘要写入记录 md「情境档案」节 → 进入《05-2 本命分析》。
