# 05-0 引擎调用规范

> 本文件定义「贞观紫微引擎」（Node CLI）的调用方式、输出字段、JSON→记录md映射、node可用性检查、回归校验。agent 排盘一律经此规范调引擎，禁止自行推算宫位干支/星曜/四化。

## 一、node 可用性检查（调引擎前必做）

agent 首次调 engine-cli.mjs 前，按三步确保 node 可用。**跨平台**（Windows / macOS / Linux / 鸿蒙等）查找逻辑见下方脚本。

### 步骤

1. **找 node**（按优先级）：
   - WorkBuddy 受管 node：`~/.workbuddy/binaries/node/versions/*/node`（macOS/Linux/鸿蒙）或 `~/.workbuddy/binaries/node/versions/*/node.exe`（Windows）
   - 系统 node：`command -v node`
2. **找不到 → 用 install_binary 装 node**：调 WorkBuddy 的 install_binary 工具安装受管 node，装完再用步骤1重找。
3. **install_binary 也失败 → 告知用户**：「排盘需要 Node.js 环境，自动安装失败，请手动安装 Node.js（https://nodejs.org）后重试」。

### 跨平台查找脚本（agent 调 CLI 前先跑，拿到 NODE_BIN 变量）

```bash
# 兼容 Windows(Git Bash) / macOS / Linux / 鸿蒙
NODE_BIN=""
for p in ~/.workbuddy/binaries/node/versions/*/node ~/.workbuddy/binaries/node/versions/*/node.exe; do
  [ -f "$p" ] && NODE_BIN="$p"
done
[ -z "$NODE_BIN" ] && NODE_BIN=$(command -v node 2>/dev/null)
[ -z "$NODE_BIN" ] && { echo "NODE_NOT_FOUND"; exit 1; }
echo "$NODE_BIN"
```

agent 拿到 `NODE_BIN` 后，本文件后续所有 `node engine-cli.mjs ...` 调用都替换为 `"$NODE_BIN" engine-cli.mjs ...`。

### 纪律

- agent 永不要求用户预装 node（WorkBuddy 自带受管 node，99% 情况步骤1即可）
- agent 永不写死 node 路径（用户名/版本号/平台各异），一律用上述脚本动态查找
- agent 永不自行算时辰索引——CLI 内部经 calcTrueSolarBranch 算真太阳时（含经度校正+均时差），agent 只传钟表时分+省市/经度

## 二、CLI 用法

引擎入口：`ziwei-chart/engine-cli.mjs`（相对 skill 根目录）

```bash
node engine-cli.mjs <年> <月> <日> <时> <分> <male|female> [省] [市] [选项]
```

- 时分为钟表时间（北京时间），引擎内部转真太阳时时辰索引
- 省市用于查经度（PROVINCES 数据库）；**正常流程必须索要到省市**，缺省时的兜底经度为北京（**116.4°E**，与 `FALLBACK_LONGITUDE` 常量一致）——用兜底值须向用户明示"按北京经度排盘"
- **城市未收录回退（必须核对）**：县级市／区县可能不在 PROVINCES 库中，引擎此时**静默回退**到上级或邻近城市经度（JSON 中可见实际使用的 `longitude`）。agent 必须核对输出经度与命主实际出生地是否一致；不一致时查明出生地实际经度，以 `--longitude` 重排，并向用户明示（回退差可达数分钟真太阳时，极端时跨时辰）。
- **城市名后缀即触发回退（实证事故）**：城市名**一律不带"市/县/区"后缀**（如库中条目为"某某"，就只写"某某"，不写"某某市"）。带后缀的名字在库中查无此项，引擎不报错、静默回退到该省 `cities[0]` 的经度（实证：真太阳时偏移由 +3 分变 −3 分，时辰整体移位，命宫挪宫、大限盘十二宫全错位，且错盘四化也能自洽、光看输出看不出来）。
- **每次调引擎的三项校验（本命/大限/流年通用）**：
  1. 核对输出 `birthInfo.longitude` 与 `_offsetMin` **与本命建档时一致**——不一致即城市名解析出了问题，立即排查重排；
  2. 大限盘调出后，核对 `daxianPalaceBranch`（大限宫干支）与 `chart.json` 的 `daXians[idx].palaceBranch` **一致**——不一致即盘面错位，禁止解读；
  3. 大限四化须与"大限宫天干→《03-1》四化表"对得上——错盘的四化常整体偏移一宫，此步是兜底。
- 也可用 `--longitude <度>` 代替省市（可单独使用，无需同时给省市；与省市同时给出时以 `--longitude` 为准）
- 选项可出现在任意位置，位置参数按「年月日时分性别 省市」顺序取，中间跳过选项（v1.1.0 修复：早期版本 `--longitude` 单独使用会被误吞为城市名而失效）

| 选项 | 作用 |
|---|---|
| `--format json\|html` | json 输出结构化命盘 JSON；html 输出单文件内联排盘 HTML（file:// 双击可用） |
| `--daxian <idx>` | 取第 idx 个大限（daXians 按 startAge 升序，idx 从0起） |
| `--liunian <年>` | 取该流年（公历年） |
| `--out <路径>` | HTML 输出路径（默认**用户当前工作目录**下 `<名>-<日期>-排盘.html`，不写入 skill 目录） |
| `--name <名>` | 命主名 |

### 调用示例

```bash
# 本命盘 JSON
node engine-cli.mjs 1990 5 5 14 30 male 北京市 北京

# 本命盘 + 预排盘 HTML（给用户看）
node engine-cli.mjs 1990 5 5 14 30 male 北京市 北京 --format html --name 张三

# 第4大限 JSON（35-44岁，idx=3）
node engine-cli.mjs 1990 5 5 14 30 male 北京市 北京 --daxian 3

# 第4大限 + 2027流年 JSON
node engine-cli.mjs 1990 5 5 14 30 male 北京市 北京 --daxian 3 --liunian 2027

# 只给经度、不给省市（溧阳 119.48°E）
node engine-cli.mjs 1987 11 13 15 30 female --longitude 119.48 --format html --name 匿名
```

## 三、JSON 输出字段

### 本命盘（type: "natal"）
- **birthInfo**: {year,month,day,hour(时辰索引),minute,gender,name,province,city,longitude,_clockHour,_offsetMin,_shichenName}
- **chart**:
  - lunarInfo: {lunarYear,lunarMonth,lunarDay,yearStem,yearBranch,isLeapMonth,lunarText,ganzhiYear,ganzhiMonth,ganzhiDay}
  - mingGongBranch / shenGongBranch: 命宫/身宫地支索引(0-11)
  - wuxingJu / wuxingJuName: 五行局数(2-6) / 名称(如"土五局")
  - ziweiPos: 紫微星地支索引
  - palaces[12]: {branch,stem,name,stars[],daXianAge,isMingGong,isShenGong,isCurrentDaXian,oppositeBranch,isEmpty,borrowedFromName,borrowedStars}
    - stars[]: {name,type(major/lucky/sha/minor),brightness(bright/normal/dim),brightnessText(**庙/旺/得/利/平/不/陷——共七值**),siHua(禄/权/科/忌/null)}
      - **亮度可用范围（2026-10-07 修复后）**：`brightnessText` 有值者＝十四主星 ＋ **文昌、文曲、火星、铃星、擎羊、陀罗**；其余（左辅、右弼、天魁、天钺、禄存、天马、地空、地劫、全部杂曜）引擎数据源无亮度，`brightnessText` 恒为 `''`、`brightness` 恒为 `normal`。此类星**不得据地支反推庙陷**，涉"入庙"条件一律判为**不成立**（见《00-2》三节、《00-4》四节）。
  - daXians[]: {startAge,endAge,palaceBranch,palaceName}
  - currentAge / currentDaXianIndex
  - **selfTransforms[]**: 宫干四化**二类** {palaceBranch,palaceName,stem,type(离心/向心),star,hua,targetBranch?}——**两式皆属自化**（《03-3》三节）：**`离心`＝四化落本宫**（星坐本宫，能量外散）、**`向心`＝四化落对宫**（星坐对宫，能量内聚，`targetBranch` 即对宫）。记录 md 的"自化"栏**两式皆收**，且须按 `type` 注明落宫；**不得把向心条目笼统写作"某宫自化X"**（会指错宫位）

### 大限（type: "daxian"）
- dxIndex, startAge, endAge, daxianPalaceBranch, daxianPalaceName, daxianStem
- daxianSiHua: {stemIndex,stemName,transforms:{禄,权,科,忌},overlay}
- overlay[12]: 大限12宫叠本命 {daxianPalaceName,natalBranch,natalPalaceName,natalStars[]}
- **daxianStars[12]**（v1.1.0）：大限动态星，按本命宫序 {natalBranch,natalPalaceName,scopePalaceName,stars[{name,base}]}，白名单含**运羊/运陀/运禄/运马/运昌/运曲/运魁/运钺/运鸾/运喜**（base=本命对应星名）；取不到为 null（horoscope 不可用或层干支校验不符），此时按无动态星处理，禁止自行推算
- **branchLookup[12]**（v1.1.0）：按 natalBranch 0-11 定序的查表摘要 {natalBranch,natalPalaceName,scopePalaceName,scopeSiHua[],dynStars[]}——地支→本命宫→大限宫映射、大限四化落宫、动态星落宫一表查全，**跨层冲照 checklist 直接查此表，禁止手工重建映射**（防对错行）

### 流年（type: "liunian"）
- year, yearStem, yearStemName, yearBranch, yearBranchName, ganzhi
- liunianPalaceBranch, liunianSiHua:{...}, overlay[12]
- **liunianStars[12]**（v1.1.0）：流年动态星，结构同上，白名单含**流羊/流陀/流禄/流马/流昌/流曲/流魁/流钺/流鸾/流喜**；取不到为 null，同上处理
- **branchLookup[12]**（v1.1.0）：结构同上（scopePalaceName=流年宫名）

### 大限+流年（type: "daxian_liunian"）
- daxian: getDaXianDetail 结果
- liunian: getLiuNianDetail 结果

## 四、JSON → 记录 md 映射

记录 md 模板沿用 05-1 附录（不变），填充源从"识图"变"JSON 映射"：

| md 字段 | JSON 来源 |
|---|---|
| 命主 | birthInfo.name \|\| '匿名' |
| 性别 | birthInfo.gender (male→男,female→女) |
| 生辰四柱 | lunarInfo.ganzhiYear年 lunarMonth月lunarDay日 _shichenName +（阳历 year-month-day _clockHour:minute，真太阳时差 _offsetMin 分，经度 longitude°E） |
| 排盘来源 | 贞观紫微引擎 v1（iztro） |
| 命宫位置 | BRANCHES[mingGongBranch]宫 |
| 身宫位置 | BRANCHES[shenGongBranch]宫 |
| 五行局 | wuxingJuName |
| 十二宫配置表 | 遍历 palaces（命宫起顺时针）：宫干支=STEMS[stem]+BRANCHES[branch]；主星(亮度)=stars.filter(major).map(name(brightnessText))；六吉(亮度)=filter(lucky).map(name(brightnessText))；六煞(亮度)=filter(sha).map(name(brightnessText))；杂曜=filter(minor)；四化=stars.filter(siHua).map(name化siHua)——`brightnessText` 为空者星名后照填 `()`（规则见《05-1》附录） |
| 生年四化 | 按 yearStem 查四化表 → 找含该星的宫 → star化sh(palaceName) |
| 自化表 | selfTransforms **两式皆收** → {palaceName,type,star,hua,落宫}；离心＝星坐本宫、向心＝星坐对宫，**均属自化、取象相反**，须标明落宫（《03-3》三节） |
| 大限区间表 | daXians → startAge-endAge \|\| STEMS[宫干]BRANCHES[宫支] |

## 五、大限 idx 与年龄映射

daXians 按 startAge 升序，idx 从0起。agent 按"问35-44岁大限"匹配 `startAge<=35 && endAge>=44` 的 idx。

## 六、已知限制

- **动态星白名单（v1.1.0）**：大限输出运羊/运陀/运禄/运马/运昌/运曲/运魁/运钺/运鸾/运喜，流年输出流羊/流陀/流禄/流马/流昌/流曲/流魁/流钺/流鸾/流喜（经 iztro horoscope API，已校验层干支对齐）。**年解不输出**（知识库无判定规则）；月运/日运/时运动态星不输出，分析时不得自行补推。计分规则：煞见《00-4》二之二节，吉曜见《00-1》动态辅佐。
- **iztro vs 文墨天机口径**：引擎盘为唯一权威源，不再对照文墨天机。已知差异（星曜庙旺表、大限起运岁）见回归校验记录。
- **命主星/身主星**：引擎不输出，不入档（保留原纪律）。

## 七、回归校验（上线前必跑）

> 注：以下预期值以**引擎 iztro 算法 + 真太阳时（含经度校正+均时差）**为准。文墨天机/records 旧识图记录用120°E未做经度校正，命宫等会差1宫，已废弃。

1. **库可用性**：`node -e "globalThis.self=globalThis; const i=require('./lib/iztro.min.js'); const l=require('./lib/lunar.js'); console.log(typeof i.astro, typeof l.Solar)"` → object object
2. **本命回归**：`node engine-cli.mjs 2026 7 25 17 7 female 北京市 北京`（北京116.4°E，真太阳时-21分→申时），核对：命宫亥(11)/身宫卯(3)/五行局木三局/丙干四化天同禄(父母)天机权(交友)文昌科(田宅)廉贞忌(夫妻)/自化6条
3. **HTML 回归**：上例 `--format html`，双击打开十二宫星曜/四化/大限面板显示正确
4. **大限回归**：`--daxian 3`（33-42岁），女命丙年逆行→大限宫在申(8)=子女宫，daxianStemName=丙、四化={天同禄/天机权/文昌科/廉贞忌}（同生年干，因申宫天干恰为丙）；**动态星（v1.1.0）**：daxianStars 中运禄在巳(5)、运羊在午(6)、运陀在辰(4)、运马在寅(2)、运昌在申(8)、运曲在午(6)、运魁在亥(11)、运钺在酉(9)、运鸾在未(7)、运喜在丑(1)
5. **流年回归**：`--liunian 2027`（丁未）四化={太阴禄/天同权/天机科/巨门忌}；**动态星（v1.1.0）**：liunianStars 中流禄在午(6)、流羊在未(7)、流陀在巳(5)、流马在巳(5)、流昌在酉(9)、流曲在巳(5)、流魁在亥(11)、流钺在酉(9)、流鸾在申(8)、流喜在寅(2)

6. **非主星亮度回归（2026-10-07 新增）**：上例女命中，非主星带亮度者应**恰为** —— 文昌(陷·田宅)、文曲(得·父母)、火星(得·夫妻)、铃星(利·命宫)、擎羊(陷·疾厄)、陀罗(庙·交友)；左辅/右弼/天魁/天钺/禄存/天马/地空/地劫及全部杂曜 `brightnessText` 应**全为空**。若非主星一律为空 → 引擎回退到写死值，须排查 `js/ziwei-engine.js` 星曜组装段（minorStars / adjectiveStars）。

校验全过方可交付解盘；任何不符先排查引擎/调用，不在分析层强行解释。

## 八、iztro 宫位排列说明（防误判）

iztro 的12宫**逆时针排**（命宫起逆时针：命→兄→夫→子→财→疾→迁→友→官→田→福→父）。例如命宫在亥，则田宅在寅（不是申）、子女在申（不是寅）。agent 分析叠宫时以引擎 `palaces[].branch` + `palaces[].name` 为准，禁止凭记忆推宫位地支。
